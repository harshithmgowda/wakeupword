# ------------------------------------------------------------- post-mortem
# Why the "far?" labels were wrong, written down so the same mistake is not
# repeated. The measurements in this file were real; the taxonomy built on
# top of them was not.
#
# 1. STRUCTURAL: "far" was a RESIDUAL BUCKET BY CONSTRUCTION.
#    classify_conditions.py labels every clip above --reference-max-index as
#    exactly one of music/whisper/far, capped at --per-speaker-music 5 and
#    --per-speaker-whisper 5 (lines 111-112, 157-164). Everything left over
#    is forced into "far" -- it was never a positive identification, exactly
#    as the block header admits. speaker_a actually has 12 music clips; a cap of
#    5 made mislabelling 7 of them unavoidable no matter how good the
#    statistics were.
# 2. IGNORED EVIDENCE ALREADY IN THE REPO. labels.tsv, produced by
#    label_clips.sh (a listen-and-label-BY-EAR tool), already recorded
#    speaker_a_29-40 and speaker_b_31-35 as "music" -- including every clip this file
#    later called "far?". The two files were never reconciled. labels.tsv
#    was also incomplete (speaker_b_36-40 had no rows until 2026-07-29), which
#    probably made it look less authoritative than it was.
# 3. THE STATISTIC WORKED; THE TAXONOMY DIDN'T. The energy-floor measure
#    (floor 0.41-0.53 for speaker_b_36-40) was real signal -- it was ranking
#    MUSIC LOUDNESS, and those 5 clips are a subset of the verified
#    louder-than-speech 7. It was read as a music/not-music boundary when it
#    was actually a music-LEVEL gradient. A statistic that separates cleanly
#    can still be answering a different question than the one asked.
# 4. "VERIFY BY EAR" WAS WRITTEN AND THEN NOT ENFORCED. The YAMNet failure
#    mode was correctly diagnosed (it fails on speech-dominant mixtures) and
#    the fallback statistic was correctly flagged LOW confidence -- but the
#    fallback was never checked against a single listened sample before
#    being written out as labels, and those labels were then consumed by
#    eval, split and reporting tooling for months. A LOW-confidence label
#    that nothing blocks on is indistinguishable in practice from a
#    confident one.
#
# Downstream effect of this correction: it changes what make_v7_split.py's
# cross-reference PRINTS, but NOT the v7 split itself -- make_v7_split.py
# builds the split purely from eval_results/v6.json scores (categorize(),
# build_split()); load_conditions() feeds the report section only.
